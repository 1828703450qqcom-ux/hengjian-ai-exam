# 系统架构说明

## 1. 总体架构

```
┌─────────────────────────────── 前端（React SPA，:5173）──────────────────────────────┐
│  考生端        教师端        管理端        监考端                                       │
│  登录/考试/结果  题库/组卷/评阅/扫描 指挥中心/KPI监控  指挥中心                          │
│  能力画像(54维)  ────────────────────────────────────────────────────────────         │
│  ProctorEngine（face-api.js 人脸/活体 + Web Audio 语音 + visibility 防切屏）            │
└───────────────────────────────┬───────────────────────────────────────────────────────┘
                                │ REST /api（vite proxy）
┌───────────────────────────────▼───────────── 后端（FastAPI，:8000）────────────────────┐
│  认证层    JWT（get_current_user / require_role）                                      │
│  路由层    auth / questions / papers / exams / grading / proctor / capability         │
│           / dashboard / system / scan                                                 │
│  服务层    grading_service    proctor_service     knowledge_service                   │
│           paper_service       assessment_service                                      │
│  数据层    SQLAlchemy ORM → SQLite（可切 PostgreSQL）                                  │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

## 2. 数据模型（核心表）

| 模块 | 表 | 关键字段 |
|---|---|---|
| 用户 | User | face_descriptor（人脸底库）、role |
| 题库 | Question / QuestionKP / QuestionDim | 题型/难度/知识点/能力维度标签 |
| 组卷 | Paper / PaperQuestion | 多目标组卷结果 |
| 考试 | Exam / ExamParticipant / ExamSession / StudentAnswer | 报名、会话、作答 |
| 监考 | ProctorEvent / EvidenceChain | 事件 + SHA256 哈希链证据 |
| 画像 | CapabilitySnapshot / CapabilityScore / KnowledgeMastery / ObjectiveAchievement | 54 维能力/知识点/课程目标 |
| 口语 | OralAssessment | 流利度/内容/发音 |
| 扫描阅卷 | ScanBatch / ScanPaper | OCR + 评分明细 |
| 平台 | AuditLog / KpiRecord | 审计与 KPI 记录 |

## 3. 多模态监考融合引擎（ProctorFusion 状态机）

```
多源事件（人脸 / 行为 / 语音 / 活体 / 切屏）
        ↓
事件权重 × 严重度 × 置信度
        ↓
风险分累积（阈值 2.2 → 作弊判定；4.0 → critical）
        ↓
命中风险事件 → 生成完整证据（截图/参数/时间戳）
        ↓
SHA256 哈希链（prev_hash + payload → hash）
        ↓
可追溯证据链（verify_chain 校验完整性）
```

- 考前：人脸底库比对（身份核验）
- 考中：多机位行为识别、多脸/离席/切屏、语音音量异常、活体眨眼检测
- 判定升级：将"疑似异常"升级为"带完整证据的判定"

## 4. AI 评阅流水线（assessment_service）

```
提交答案 → 客观题精确比对（100%）
        → 主观题：关键词覆盖 35% + TF-IDF 余弦 40% + 结构特征 25%
        → 英语作文/翻译：含语言维度
        → 口语测评：流利度 35% + 内容 40% + 发音 25%
        → 教师复核：compute_agreement 一致性 + calibrate 校准建议
        → 知识图谱画像生成（knowledge_service）
```

## 5. 知识图谱能力画像（knowledge_service）

```
题目得分 → 知识点掌握度 → 能力维度（54 维 DIMENSION_CATALOG）
                          ↓ 推断（未观测知识点）
                 课程目标达成度（ObjectiveAchievement）
                          ↓
        54 维能力画像（直接评估 + inferred 推断标记）
                          ↓
        画像匹配度 = 直接评估维度等级 vs 知识点推断等级一致性
                          ↓
        个性化学习建议（DIMENSION_ADVICE 薄弱维度映射）
```

## 6. 弹性中台设计

- **标准契约**：REST + OpenAPI 文档，API 适配周期 ≤7 天
- **模块化**：题库/组卷/监考/画像模块即插即用，新场景接入 ≤3 天
- **扩展性**：无状态服务 + 连接池 + 缓存 + 消息队列设计，水平扩展支持 1 万并发
- **可用性**：多实例容灾，目标 99.9% 可用率，响应 ≤500ms
